# Backup and restore review

The panel lists existing backup sets, offers read-only archive inspection, and lets admins download backup files. Restore is disabled by default (`restore_enabled: false`). The root helper only accepts a named vanilla/SkyFactory archive from a completed backup set, checks that the archive matches the selected server, rejects traversal, links and special files, limits entries and expanded bytes, checks reserve space, stages before stopping the server, retains the old root as rollback, preserves current RCON settings, and restores the prior active/inactive service state. Restore fixture tests cover traversal and failure/rollback paths in the helper.

The repository contains an existing maintenance service/timer and user-provided environment says three successful sets exist, but live maintenance script `/usr/local/sbin/minecraft-maintenance`, retention cleanup, backup permissions, locking, failure recovery, integrity and available storage could not be inspected: SSH sudo requires an interactive password and the script is root-only. These are **NOT VERIFIED**, not assumed safe. Do not enable restore until a separate isolated Debian review verifies the helper/script and lock interaction.

Backups and worlds share the same USB device. A drive failure or theft can remove both; retain encrypted, access-controlled copies on separate storage and periodically restore into an isolated test directory. Admin downloads contain private world/player data and may include historical server credentials; handle as secrets. No live restore or backup operation was triggered.
