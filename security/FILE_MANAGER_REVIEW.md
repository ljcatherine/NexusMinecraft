# File manager review

`safe_path` resolves the fixed server root, rejects absolute/parent/traversal/Windows-style paths, checks each path component for symlinks and verifies the final resolved path remains under the server root. `check_file` denies `server.properties`, names matching password/secret/token/credential/private-key, internal `.panel-*` paths and world-data mutation. Writes are limited to selected text suffixes, JSON/YAML are parsed before save, writes use a temporary file plus atomic replace, revisions prevent stale writes, and edit snapshots are made. The generic file uploader accepts text/config formats only. A dedicated admin-only extension route installs a validated ZIP/JAR into the fixed plugin or mod directory, requires an explicit trust confirmation, rejects unsafe filenames and overwrites, and streams to an atomic temporary file with a 64 MiB limit. Archive inspection rejects traversal, links and special files.

Read-only fixture tests cover parent traversal, symlink escape, RCON settings exclusion, file validation, stale revision and archive traversal. The viewer file-read authorization weakness was confirmed by route code and fixed: file contents now require admin, while viewers can still list the file tree and use the separate read-only dashboard/log APIs. Regression tests assert 403 for viewer file reads/downloads.

Residual risks: path checks are vulnerable to a local concurrent symlink swap between check and use; hostile plugins run as `ps5` and can change files in the roots. Use descriptor-relative no-follow operations (`openat2`/`O_NOFOLLOW`) if local/plugin adversaries enter the threat model. Each request is capped at 65 MiB including multipart overhead, but concurrent authorized requests can consume temporary storage. JARs receive a deliberate trust confirmation, but the panel does not verify publisher signatures or remote provenance. A JAR executes when the corresponding server loads it, so admin access remains equivalent to trusted server operator access.
