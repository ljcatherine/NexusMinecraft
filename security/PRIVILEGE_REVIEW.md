# Privilege and system integration review

The FastAPI process runs as `ps5-panel`, not root. The systemd unit applies `ProtectSystem=strict`, `ProtectHome`, `PrivateTmp`, kernel/control-group protections, resource limits, a restrictive address-family list and explicit writable paths. The service joins `ps5` and `systemd-journal` groups to access server files and logs. This access is broad within the two Minecraft roots and means compromise of the panel can damage server data.

The application uses argument arrays for subprocesses. `system.py` does not use a shell. The sudo target is a root-owned fixed path `/usr/local/libexec/ps5-panel-helper`; the helper uses isolated Python (`-I`), clears environment, fixed `/usr/bin` executables, fixed unit/server allowlists and rejects arbitrary commands/paths. It supports start/stop/restart of two Minecraft units, start-only maintenance, and a config-locked restore. This is materially narrower than unrestricted root shell. The unit intentionally lacks `NoNewPrivileges` so the narrowly authorized sudo transition can work.

Live `systemd-analyze security ps5-panel.service` reported 7.4 MEDIUM. This aggregate score includes deliberate tradeoffs such as supplementary groups and sudo. Unit status and process user were checked. The following were **NOT VERIFIED** due sudo requiring an interactive password: loaded sudoers syntax, root-owned ACLs, polkit/D-Bus, capabilities, world-writable paths, setuid inventory, SSH policy, maintenance script. Repository files show the intended configuration but are not proof of live configuration.

Minecraft and the SSH account both run as Unix user `ps5`. A malicious plugin executes with that user's filesystem/SSH authority. This is a substantial host boundary limitation; do not install untrusted extensions or give panel admin to untrusted users. Longer-term, move Minecraft to a dedicated account distinct from SSH, and remove SSH keys/access from the Java runtime identity, with a carefully planned ACL and service migration.
